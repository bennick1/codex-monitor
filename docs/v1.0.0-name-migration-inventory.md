## 3. Identifier 与升级评估

V1 建议保留 `app.quotafloat.desktop`。名称改为 Codex Monitor 并不要求更换 identifier。`lib.rs` 用 `app_config_dir()` 保存 preferences，用 `app_local_data_dir()` 保存 `token-statistics.sqlite3`；macOS window-state 还使用 app config 目录。标识更换会切换配置、SQLite、WebView 状态、单实例身份及系统集成。SQLite 保存了可能已删除 session 的历史统计，不能当缓存重建。

| 平台 | 当前位置 | 若改成新 identifier |
| --- | --- | --- |
| macOS | `~/Library/Application Support/app.quotafloat.desktop/`（配置/SQLite） | 变成新的目录，旧统计不会自动出现 |
| Windows | `%APPDATA%\app.quotafloat.desktop`（配置）；`%LOCALAPPDATA%\app.quotafloat.desktop`（SQLite） | 旧偏好和累计数留在旧目录 |
| Codex 输入 | `CODEX_HOME` 或 `~/.codex` | 与应用 identifier 无关，保持不变 |

保留 identifier 也**不等于旧安装升级已验证**：productName 改动会影响 `.app` 文件名、Windows 安装目录/开始菜单、注册表，WiX 默认 upgradeCode 还依赖 productName。V1 主 Windows 安装包采用 NSIS `.exe`，按普通用户 currentUser 安装验收；旧版迁移需退出旧进程、备份完整数据、关闭旧开机启动并核对新安装入口。旧包和新包不要并行启动。卸载时不得选择删除用户数据；全新安装通过不能代替升级测试。

未来若改为 `io.github.bennick.codexmonitor`，必须单独实现并双平台验证：退出所有旧实例 → SQLite backup API 一致性备份并核验（不可单拷活跃主库遗漏 WAL）→ 目标不存在才迁移配置/位置/数据库 → 校验数据库完整性、schema 和各统计周期/检查点 → 写迁移标记 → 保留旧目录和回滚说明。若目标已有数据则停止并明确报错，禁止覆盖或自动合并。不把本轮名称整理扩展为这项数据迁移。

参考：[Tauri identity/productName 配置](https://v2.tauri.app/reference/config/#productname)、[WiX upgradeCode](https://v2.tauri.app/reference/config/#wixconfig)、[Updater 签名要求](https://v2.tauri.app/plugin/updater/)。路径同时以本机已锁定 Tauri 实现核验。
