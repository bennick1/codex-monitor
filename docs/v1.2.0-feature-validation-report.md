## Feasibility and data contract

All four Phase 0 gates are Confirmed; see [feasibility](v1.2.0-turn-quota-feasibility.md). Effort is exactly `turn_context.payload.effort`, stored without inference; display normalization only. Model comes from `turn_context.payload.model`. Response records explicitly bind thread/turn/response identities. `event_msg.payload.type = task_complete` uses `payload.completed_at` in Unix seconds. Start, successful completion and abort are distinct parsed events; aborts and contradictory completion timestamps do not produce precise rows.

Schema 2 to 3 adds effort/conflict/completion columns, `quota_snapshots` and metadata indexes. All DDL, metadata-checkpoint reset and `user_version` mutation are transactional. Early, intermediate and final-DDL injected failures restore the original schema, metadata checkpoints and accounting facts; restart is tested. Accounting parser version remains 1. Only supplementary metadata is rescanned; accounting cursors, active/reconciled fact rules, definitions, deduplication and normalization semantics remain unchanged. Regression tests compare Overview and By Model amounts before/after migration and rescan. Legacy attribution requires the existing exact fact/source ownership evidence. No independent usage ledger is introduced.

The third Token mode uses one reliably completed turn per row, sorted oldest first in the current real weekly quota period. It does not group sessions/tasks or collapse repeated model/effort combinations. Tokens aggregate existing eligible active facts and cross IPC as decimal strings, formatted with BigInt. Model conflicts are explicitly unidentified; effort conflicts/missing fields show a dash. Unproven fact ownership is excluded. Future facts retain existing time deferral.

## Quota observations

Only an existing fresh successful Codex provider refresh can persist a valid weekly observation. Cache reads do not create observations. No additional HTTP requests, completion-triggered requests or polling were added. Debug 5h display overrides run after persistence.

- Valid weekly period: canonical `resetsAt`, duration exactly 604800 seconds, start at reset minus 604800 seconds; no natural-week fallback.
- Valid finite original percentage: inclusive range 0–100, preserved as SQLite REAL without UI rounding in storage; invalid percentages explicitly reject.
- Observation records actual refresh observation time and resolved source root. Missing/unresolved root skips persistence rather than guessing.
- Association: same reset period, first observation at/after completion, inclusive maximum 15 minutes, never later than query time. No earlier/cross-period/interpolated observation.
- Parallel turns may share one observation. Percentages may rise, including provider/reset-credit behavior; no monotonicity constraint.
- No eligible history means null / dash. Current quota is never used to infer old percentages.

## UI and native geometry

Three skins and two languages retain the established design. Expanded Default/Computer decorations are removed; Orb, Computer background/stripes and error assets remain. Absent shortWindow with available weekly quota removes the whole 5h block. Provider error states and Reset Credit remain.

All user-visible Incomplete text, including tooltip and aria additions, is removed; internal partial state and numeric `*` remain. By Turn has separate model, effort, exact Token and weekly observation columns, full-model hover, right-aligned numeric columns and internal list scrolling. No second period selector is added. Quota-boundary changes immediately clear old turn rows, including delayed or failed queries. High-precision percentages use an ellipsis in the narrow column while preserving full precision in the focus/hover tooltip and accessible label; both tooltips were visually checked above the internal scroller.

A 36-case real Chromium matrix measured visible dimensions **306×506** (full) and **306×452** (compact). With the existing 4px safe inset, native logical dimensions are **314×514** and **314×460**. CSS and Rust use these deterministic modes; serialized expand/collapse/appearance transitions prevent races. Height growth updates native geometry and clamps in the monitor work area. Tests cover both modes at multiple scales, bottom/right anchoring, negative-origin monitors and small bounds. No content-driven ResizeObserver is used. A concurrent height/theme sync during the first expanded drag preserves the current position instead of returning to the old collapse anchor; a dedicated regression test covers both heights.

Token content moves upward (full 284px, compact 230px); By Model list viewport measures 115–117px versus the previous 88px, and By Turn 117–119px. Sparse lists can still leave unused list space because heights are deterministic. Browser checks found and fixed outer focus scrolling caused by decorative overflow; only lists scroll. This matrix is layout evidence, not human acceptance.

## Known limitations and remaining gates

- Weekly quota is an account Provider Snapshot, not one turn's independent consumption; parallel turns may share it and provider timing may lag.
- Pre-v1.2 quota history does not exist; old rows may show a dash. The 15-minute maximum can also leave recent rows without observations.
- Observations arriving before source-root resolution are skipped. Failed DB persistence does not add an HTTP retry; a later normal refresh may provide another eligible observation.
- Token amounts remain local Codex log statistics; there is no cross-device merge or official Token-to-Quota conversion.
- Metadata sampling does not prove all historical log formats; absent/unreliable fields remain unknown.
- Previous small-size branding review is Superseded / Invalidated. CM runtime reconstruction, technical validation and current CM material human acceptance are complete; actual native Tray selection/legibility remains outstanding.
- Actual macOS menu-bar light/dark readability, Tray menu, fullscreen Space, dock/edge clamp, pure-hover cycles and Windows real-machine Tray/click/drag remain outstanding.
