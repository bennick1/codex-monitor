# v1.2.0 Turn quota feasibility

## Decision

| Gate | Result | Evidence contract |
| --- | --- | --- |
| Turn Identity | Confirmed | `session_meta.payload.id` equals `token_usage_record.payload.thread_id`; `turn_context.payload.turn_id` equals the record's `payload.turn_id`; `payload.response_id` provides response identity. |
| Model | Confirmed | `turn_context.payload.model` is explicit metadata for that turn. |
| Reasoning Effort | Confirmed | **`turn_context.payload.effort`** is explicit turn metadata. Observed enum examples: `low`, `medium`, `high`. |
| Turn Completion | Confirmed | `event_msg` with `payload.type = task_complete` carries the same `payload.turn_id`; `payload.completed_at` is an integer Unix timestamp in **seconds**, consistent with the envelope RFC3339 `timestamp`. |

## Read-only investigation

A bounded sample of recent JSONL files from both `CODEX_HOME/sessions` and `CODEX_HOME/archived_sessions` was inspected. Only metadata paths, enum values and structural comparisons were emitted. No raw identities, model usage history, token counts, quota percentages, content, credentials or machine paths are included here.

`event_msg.payload.type = task_started` establishes a distinct start event. `task_complete` establishes successful completion. `turn_aborted` has its own completion timestamp but must not create a completed-turn row. Start/completion IDs matched explicit turn contexts in the sample. Numeric lifecycle timestamps were checked against envelope timestamps and, where available, `duration_ms`; they are seconds, not milliseconds.

## Implementation recommendations

- Preserve accounting parser/rule version and normalization semantics. Add supplementary effort and lifecycle metadata; process the three lifecycle variants separately while retaining their existing attribution-boundary behavior.
- Store only explicit effort strings. Missing effort stays null; contradictory explicit values must remain unknown. Never infer from models, token composition, neighboring turns or user habits.
- Require reliable identity, model and successful completion for precise rows. Do not manufacture ownership for uncertain legacy ranges. Aggregate existing active facts through existing identities; never create a second accounting ledger.
- Upgrade schema 2 to 3 additively in one transaction, including all indexes and metadata version changes. Rescan only metadata through independently checkpointed processing; never replay historical facts through normalization.
- Persist valid weekly observations from successful existing refreshes, without additional requests. Associate the first observation at or after completion within 15 minutes in the exact same reset period. Missing historical observations remain null.

## Known boundaries

Sampling confirms real field contracts, not universal presence in all historical versions. Missing or conflicting metadata must remain unknown. Older lifecycle records without a valid explicit completion time require conservative exclusion. An aborted or contradictory lifecycle is not reliable successful completion. Account quota observations may be delayed and shared by parallel turns; they are not per-turn quota consumption.
