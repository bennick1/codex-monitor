## Reproduction and root cause

**Confirmed: TokenUsage mousedown propagates into the card drag handler.**

Before changing production code, the real `QuotaCard` rendering its real `TokenUsage` was tested with an `onDrag` spy. No component or event propagation was mocked. The regression suite failed in three cases: By Model, model period control, and overview exact value. Each failure recorded one drag callback where zero was required. The By Model click had already changed `aria-pressed` to `true` before the drag assertion failed. The external card drag test passed.

The source call chain is:

`TokenUsage descendant mousedown → QuotaCard main.onMouseDown → onDrag → App startDragging → bridge begin_widget_drag → currentWindow.startDragging()`.

TokenUsage had no mousedown isolation on its root, view buttons, period buttons, exact values, or model list. The view and period switches update local React state; they do not initiate a statistics query. Existing card action controls already isolate mousedown.

The propagation defect is confirmed. Its role in the reported Windows native WebView delay remains subject to Windows human validation: jsdom does not reproduce native drag timing or prove the entire platform symptom is resolved.

## Minimal fix and scope

The only production change is `src/components/TokenUsage.tsx`: stop mousedown propagation at the root section. The entire TokenUsage region is excluded from card dragging. No preventDefault, click interception, pointer/touch interception, timer, artificial delay, or data-loading change was added.

`src/components/QuotaCard.test.tsx` adds four real component integration tests covering view switching, all five periods, exact-value focus/list interactions, and the external card drag area. Fixtures are synthetic.

Unchanged: Token Statistics backend, SQLite, attribution, all period definitions and APIs, Quota, bridge drag implementation and stability timer, dock/snap/monitor clamp/window geometry, skins, assets, dependencies, lockfiles, and workflows.
