## 实施与分工

三个 GPT-6.1 SOL 子智能体分别实现后端、前端、发布流程；主智能体整合、审查并操作原生 QA；另由 GPT-6.1 SOL 独立复审。

- 官方 `tauri-plugin-updater` 固定 2.9.0，保留现有 Tauri 2.11.5。后台仅检查：启动 30 秒后一次，之后每 24 小时；`autoCheckUpdates` 默认开启并可持久化关闭。下载与安装分别由用户操作。
- Rust 保持更新状态、缓存和互斥任务；关闭更新窗口不取消下载。标准窗口仅开放五项私有更新命令，远程 DeepSeek 窗口不能调用；说明按纯文本显示。
- 固定正式源 `https://github.com/bennick1/codex-monitor/releases/latest/download/latest.json`。无编译公钥的普通构建保留下载页入口并提示未配置；正式发布构建拒绝缺公钥及 QA 配置。
- GitHub 仅目标仓库 `main` 的手动流程可以发布；冻结来源 SHA，校验版本、标签、两个平台签名及包内身份，先上传完整草稿、回读核对，再公开。普通 push、PR、其他分支不发布。

## 已发现问题及处理

1. 原 QA 打包缺少 CLI 所需 `plugins.updater` overlay，编译成功但打包失败；QA 与正式脚本都补充公钥/端点 overlay，A/B 后续实际打包成功。
2. 安装失败后，已验签缓存阻止手动重新检查；仅在“安装失败＋主动检查”时清理该候选，后台与就绪状态继续保留下载缓存；回归测试及原生复测通过。
3. 发布门禁原先只验证旁边构建报告与归档签名，未绑定包内主程序。现对 Mac tar 的 plist/主程序、Windows NSIS 主程序核对身份、版本及 SHA；有效签名旧版本/错误标识/错误二进制负例通过，独立复审关闭 P2。Windows 7-Zip 实际执行仍待原生验证。
4. QA 原启动器继承命令会话；首次升级后观察到 B 的新进程，但随后消失，未发现该 PID 崩溃报告。会话结束清理是待证实解释。工具额外启动缺少 QA 隔离环境，产生两份独立启动失败报告，不能混记成更新崩溃。QA 启动器已改 detached＋文件日志＋unref，新增不覆盖已升级包的 `start`。用户解锁后继续：独立 A 已存活约 10 小时，A→B 自动重启及 B 冷启动均通过；B 的进程和原生版本在重新绑定工具前后分别核验。本轮未改产品重启逻辑；首次进程消失的具体终止原因仍未证明。
